# 工具调度器

统计模型工具的近期使用情况，统一管理开关与提供策略，在同一 Agent 中混用 Full 和 Skills-like，并按频率自动调度。

声明支持 **AstrBot >=4.27,<5** 的默认本地 `ToolLoopAgentRunner`，当前已在 4.27.4 源码上验证。插件使用请求级适配器，不修改 AstrBot 源码，不替换全局 Runner 类，也不修改原始工具 Schema 或全局 `active` 状态。

## 安装与开始使用

通过 AstrBot WebUI 上传安装包，或将本目录放到 `data/plugins/astrbot_plugin_tool_scheduler/`，然后加载插件。

打开 **工具调度器 → 工具调度** 插件页面。建议宿主的“工具调用模式”选择 **Full**，在本页面按工具控制提供策略。宿主设为 Skills-like 时也可接入；未设置固定策略且智能调度关闭时，沿用宿主默认模式。

安装后默认只统计，智能调度关闭。管理员可以先查看使用情况、设置固定策略，再打开智能调度。设置保存在插件标准数据目录，不需要重启。

## 开关与策略

“允许模型使用”与“提供策略”分别管理：

| 设置 | 行为 |
| --- | --- |
| 关闭允许使用 | 不提供、不参与工具发现；执行前再次检查，阻止尚未开始的调用 |
| 固定 Full | 立即应用，后续模型请求提供完整名称、描述和参数 |
| 固定 Skills-like | 立即恢复轻量定义；选中后补全参数并保留到会话结束 |
| 智能 / 默认 | 智能调度开启时按频率决定，关闭时使用宿主默认模式 |
| 继承默认 | 继承来源插件/MCP 的策略，来源未指定时使用智能或宿主默认模式 |

关闭来源会关闭其全部工具，包括之后新增的工具；单工具的开启不能越过来源关闭。单工具的固定策略优先于来源默认策略。AstrBot 原有的插件启停、工具启停、人格选择、用户权限仍然有效，本插件不会把宿主不允许的工具补回来。

页面的两个总开关含义不同：

- **智能调度**：控制是否自动根据频率调整提供方式；关闭后仍统计，并遵循手动开关和固定策略。
- **禁止所有模型工具**：阻止全部受管工具，包括工具发现入口。管理页面保持可用。正在执行的操作不被强制撤销，尚未开始的调用会被阻止。

本插件的开关控制受管请求中的使用许可，不等同于 AstrBot 官方工具的全局开关。内置工具的原生全局状态仍由宿主配置决定；所属插件和 MCP 服务不会被本插件启停。

## 智能调度

| 状态 | 任务开始时提供什么 |
| --- | --- |
| Full | 完整参数，模型可直接调用 |
| Skills-like | 轻量定义，选中后再补全参数 |
| 休眠 | 不放入常规工具列表，仍可通过工具发现找回 |

默认统计窗口七天。被至少十个独立请求使用的工具升级为 Full；低于五个请求并持续四十八小时才降级，避免反复切换。

工具只有在观察至少七天、统计窗口内存在至少五十次原本可用的请求、且近期无使用时才休眠。数据不足的工具保留 Skills-like，不能把“刚安装，没有数据”当作“不需要”。所有阈值可在页面修改，自动模式按 AstrBot 配置 ID 独立计算。

统计持续更新，**由使用量变化触发的自动升降级和休眠，仅在新会话或成功 `/reset` 后应用**。同一会话沿用已有策略、定义顺序、描述和 Schema；某工具首次展开完整参数后，在整个会话中保留，普通聊天轮次不会退回空参数。切回已有会话时恢复该会话的快照。列表显示新会话策略，待更新的已有会话单独标记。

**管理员修改立即生效**，包括来源及单工具开关、固定策略、智能调度开关和阈值。后续模型请求使用新定义；已经发出的模型请求无法追溯修改，尚未开始执行的工具调用仍会重新检查开关。管理员将已展开工具重新固定为 Skills-like 时，会立即清除该工具的展开状态。修改搜索别名不重置展开状态。

会话快照保存在 SQLite，重启后在保留期内可恢复，缓存命中仍由模型服务决定。首次按需展开、工具发现、管理员修改或宿主权限变化仍可能影响缓存。新注册工具通常等到新会话 / reset 纳入快照，管理员对该工具或其来源修改策略可提前纳入；工具只有在当前宿主请求本来允许时才会提供。

`/reset` 不一定改变会话 ID：插件识别宿主成功重置标记，并以历史从非空变为空作为补充判断，避免将每轮内部 Runner 的 `reset()` 误认为用户重置。没有宿主会话 ID 的独立调用仍按单次任务调度。

## 混合调用与工具发现

同一轮响应可以同时选择 Full 工具和多个轻量工具。调度器只对轻量工具发起参数补全请求，保留已有 Full 调用及其参数、调用 ID，合并后通过 AstrBot 原有执行器执行。

智能调度开启时，模型会看到 `tool_scheduler_discover`：

```text
tool_scheduler_discover(query="生成词云")
```

发现入口按名称、描述、中文词组和管理员别名检索当前请求及会话快照允许的工具。空 query 可以浏览，owner 可以按来源筛选，offset 支持翻页。匹配工具在当前会话中加载完整参数，发现操作本身不执行工具。模型仍可能漏掉发现步骤；如果某能力需要始终出现在工具列表中，可固定 Skills-like 或 Full。

参数 Schema 只在请求的工具定义中发送，不作为发现结果正文写入聊天历史。实际工具调用的名称、参数及结果仍由 AstrBot 正常保存。参数补全阶段失败时不会执行空参数占位调用，也不会丢掉同一轮中已经完整的 Full 调用。

## 统计口径

- **调用次数**：真正进入原执行器的次数。同一任务重复调用分别计数；参数不合法、权限拒绝和手动阻止不计入真实调用。
- **使用请求数**：同一 Agent 根请求内，同一个工具最多记一次，用于自动模式判定。
- **插件/来源统计**：真实调用次数汇总；使用请求数按来源去重，不是简单相加。
- 参数展开、工具发现及空参数选择不计入原工具调用。
- 错误指执行异常或标准 `isError` 返回。普通字符串中的业务失败无法可靠识别，不自动判断为错误。
- Schema Token 是粗略估算，未扣除额外模型请求成本，不表示实际 Token 或费用节省。

默认保留三十天调用记录、策略变更记录及闲置会话快照，可配置到三百六十五天。统计记录工具身份、配置 ID、随机请求 ID、时间、耗时和状态，不记录参数、聊天用户身份、聊天正文或结果；管理员变更记录保留操作人的 WebUI 用户名。会话快照仅保存工具元数据、提供模式、展开状态及经过哈希的会话索引，不保存原始会话 ID 或消息来源。工具目录中的参数定义属于元数据。数据默认位于：

```text
data/plugin_data/astrbot_plugin_tool_scheduler/scheduler.sqlite3
```

## 适配范围

当前接入默认本地 Agent 的原始请求工具集，可处理插件工具、MCP 工具及宿主内置工具。工具权限包装和原执行器保持有效。页面显示首次接入时间、活动任务及未接入次数。

第三方 Agent Runner、其他插件直接请求模型的流程、尚未接入调度器的子 Agent 不在接管范围。对 Handoff/子 Agent 入口统计入口调用，不宣称统计其内部每个工具。内置工具在具体人格和会话中的可用性仍由宿主决定，页面状态是所选配置的策略预览。

适配器读取 AstrBot 的活动 Runner 注册表，并只修改当前实例的 Schema 提供和参数补全回调。元数据版本范围为 `>=4.27,<5`；由于涉及宿主内部接口，更新 AstrBot 次版本前应重新验证。卸载或停用本插件后，恢复宿主原有工具提供方式，调度器自己的关闭策略不再执行。

默认 Agent 接管失败时，为保证手动关闭规则不被绕过，该次请求会禁用工具并记录错误日志；页面的“未接入”计数会增加。工具执行后的统计写入失败只记录日志，不改变已完成的工具结果。管理员关闭不能撤销已经开始执行的操作。

## 开发验证

将本项目与 `AstrBot` 放在同一父目录：

```powershell
..\AstrBot\.venv\Scripts\python.exe -m pytest tests -q
..\AstrBot\.venv\Scripts\python.exe -m ruff check .
..\AstrBot\.venv\Scripts\python.exe -m ruff format --check .
node --check pages/scheduler/app.js
```

也可用 `ASTRBOT_SOURCE` 指定 AstrBot 源码位置。测试使用隔离临时数据目录，覆盖真实 Runner 和原生执行器、混合调用、休眠找回、权限、计数去重、配置隔离、持久化及管理接口。

`tests/browser_preview.py` 提供仅绑定 `127.0.0.1:8767` 的页面预览，使用内存测试数据，不连接 AstrBot 实例，不包含在安装包中。

构建安装包：

```powershell
python build.py
```

生成 `dist/astrbot_plugin_tool_scheduler-0.1.1.zip`。构建仅包含插件代码、页面、元数据及说明，不包含测试数据和本地运行文件。
